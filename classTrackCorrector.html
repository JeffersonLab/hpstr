Detailed Description

One entry point for the track corrections a processor applies: it owns the individual tools and runs them in a fixed order, configured by a single JSON.

JSON keys (all optional; a missing or empty key switches that step off). Relative paths are resolved against $HPSTR_BASE.

"trackOffsets": file with constant offsets {"track_z0": x, "track_time": t} "z0Offset": {"data": file, "mc": file} per-run v0-projection z0 means (elez0_mean / posz0_mean); the closest run at or below the event's run is used "z0Calib": {"data": file, "mc": file} linear z0 calibration, z0 -= slope*tanL + intercept "momentumScale": {"runScale": file, "meanCorr": file, "meanCorrVariable": ""} data only; see RunScaleCorrectionTool "smearing": {"cfg": file, "smearingFactor": 1.0, "smearOmega": true, "variable": "tanLambda", "requireTruthMatch": false, "smearZ0": true, "trackCollection": "KalmanFullTracks"} MC only, and only when Options::doSmearing is set

Order, each step applied to all tracks before the next: trackOffsets, z0Offset, z0Calib, momentumScale (data), z0 smearing (MC), momentum smearing (MC).

Per-job settings (data/MC, seed, whether to smear, truth-match override) are not in the JSON; the processor passes them in Options.
